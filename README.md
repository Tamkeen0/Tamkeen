# Tamkeen | تمكين
Accessible STEM examination prototype for blind students. Starter only; no exam functionality implemented. Working name and interfaces are provisional until the team agrees. Check hackathon rules before using prewritten scaffolding. If prohibited, use this as planning material only and recreate allowed work during the event.

## Lead setup (before anyone branches)
1. Create an empty GitHub repository (no auto README). Prefer private if your GitHub plan supports required protections; otherwise public only if event rules permit and with no confidential data.
2. Extract the starter, cd into it, run `python scripts/configure_team.py --lead YOUR_LOGIN --frontend FRONTEND_LOGIN --document DOCUMENT_LOGIN --voice VOICE_LOGIN`. Use four actual distinct GitHub logins. `CODEOWNERS` requests the lead for all paths, including protection files.
3. `git init -b main`, `git add .`, `git commit -m "Initialize shared architecture and collaboration guard"`, `git remote add origin https://github.com/OWNER/REPO.git`, `git push -u origin main` (initial setup only; install hooks after first push).
4. In GitHub Settings, add collaborators only with minimum permissions or use read-only upstream + forks if supported. For `main`, require PRs, lead CODEOWNERS approval where supported, dismiss stale reviews, block force-push/deletion, require `scope-guard` check once it has run, and restrict merging to lead where supported. On a personal repo, collaborators with write may retain merge permissions; do not claim otherwise. For strict upstream ownership, use a repo where only the lead has write and teammates submit from forks; ensure private fork support first. Lead's own PRs cannot self-approve; configure a narrowly controlled lead-only bypass or trusted reviewer, never global bypass for collaborators. Disable auto-merge. Do not give agents GitHub admin tokens. Verify settings and a negative PR before relying on them.
5. Each teammate clones (or forks then clones; set `origin` to upstream for checks only in fork workflow and push to `fork` manually; adapt pre-push remote accordingly). Same-repo default: `git clone URL`, `cd REPO`, `git switch -c feature/ROLE`, `git config core.hooksPath .githooks`. Use assigned branch exactly. Lead: `feature/backend`. On Windows use Git Bash or WSL; Python must be available as `python`.
6. Give agent its role file under agents/ and require AGENTS.md. Use agent filesystem sandbox/OS permissions for truly read-all/write-own boundaries; ordinary hooks are bypassable and do not stop local edits. No agents get unrestricted upstream write credentials. Lead-only `integration/lead` is for explicit human-approved cross-module changes; never assign it to an autonomous agent.

## Daily workflow (same-repo default)
From assigned branch: `git fetch origin main`, `git merge origin/main` (human handles conflicts; never agent), work only assigned paths. `git status --short`, `git diff`, stage only owned files, `git commit -m "..."`, `git push -u origin feature/ROLE`. Open PR into main. Do not auto-merge. After merge, sync branch with main (avoid reusing a squash-merged branch: human may reset/recreate only after preserving all work). Small PRs, early integration.

Lead from a clean main checkout: `git pull --ff-only origin main`, `python scripts/review_pr.py PR_NUMBER` (requires authenticated GitHub CLI `gh`). This checks actual PR author, branch and changed paths using trusted local main, then prints the exact SHA-pinned merge command. Review diff and run tests before executing it. Normal PR CI reads base checkout but proposed workflow changes could tamper with CI; trusted manual review is mandatory, especially for protection files. CI alone is not an adversarial security boundary. Git hooks check staged or net changes and can be bypassed; reject any unauthorized file edits immediately. A teammate may read everything, but do not give unnecessary secrets or writable upstream permissions.

## Development
Node 20+ (22 recommended), Python 3.11+. Lead installs frontend deps from frontend/ using `npm install` and commits lockfile; `npm run dev` starts placeholder. Lead creates backend dependency manifest and starts `uvicorn backend.main:app --reload` once implemented; document agent requests dependencies first. No actual API or speech implementation included. See contracts/API.md and ARCHITECTURE.md for frozen interfaces. Mock fixture contains synthetic exam only. All roles read it; lead controls updates. No secret data in Git. Run guard unit tests: `python -m unittest discover -s scripts -p 'test_*.py'`.
